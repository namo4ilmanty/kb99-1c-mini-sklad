# Мини-Склад

Учебная конфигурация «1С:Предприятие 8.3» с минимальным контуром складского учёта:
справочники товаров и контрагентов, документы поступления и реализации, регистр остатков.
Практика первой недели курса kb99, приёмы — по занятиям 1–5 «Практического пособия разработчика»
(Радченко, Хрусталева).

## Требования

- Платформа **1С:Предприятие 8.3.27** или новее — подойдёт и версия для разработчиков.
  Выгрузка сделана в 8.3.27.2342, режим совместимости конфигурации — 8.3.27, поэтому более старые платформы её не загрузят.
- Конфигурация `МиниСклад`, версия 1.0.1.1, управляемое приложение, интерфейс «Такси».

## Что внутри

| Тип | Имя | Описание |
|---|---|---|
| Подсистема | `МиниСклад` | Раздел «Мини-Склад»: списки всех объектов, в меню «Создать» — оба документа |
| Справочник | `Товары` | Иерархический (группы и элементы), реквизит `Артикул` |
| Справочник | `Контрагенты` | Реквизит `ИНН` |
| Документ | `Поступление` | «Поступление товаров»: реквизит `Контрагент`, табличная часть `Товары` (`Товар`, `Количество`, `Цена`, `Сумма`) |
| Документ | `Реализация` | «Реализация товаров», та же структура |
| Регистр накопления | `ОстаткиТоваров` | Вид «Остатки»: измерение `Товар`, ресурс `Количество` |
| Общий модуль | `РаботаСДокументами` | `РассчитатьСумму()` — сумма строки = количество × цена |

Как это работает:

- В формах документов сумма строки пересчитывается при изменении количества или цены:
  обработчики `ПриИзменении` вызывают `РаботаСДокументами.РассчитатьСумму()`.
- При проведении каждая строка табличной части даёт запись в `ОстаткиТоваров`:
  `Поступление` — приход, `Реализация` — расход, период — дата документа.
  Код — в `ОбработкаПроведения` модулей объектов документов.
- Перед расходом `Реализация` проверяет остатки на момент документа, не считая собственных движений: если товара
  не хватает, документ не проводится, а пользователь видит, сколько нужно и сколько есть на складе.
- В документах обязательны контрагент и хотя бы одна строка товаров; в каждой строке — товар, количество и цена.

## Структура репозитория

```text
src/cf/                       выгрузка конфигурации в файлы (иерархический формат)
├── Configuration.xml         свойства конфигурации и список объектов
├── Subsystems/               подсистема и её командный интерфейс
├── Catalogs/                 справочники
├── Documents/                документы: формы (Forms/) и модули (Ext/*.bsl)
├── AccumulationRegisters/    регистр остатков
├── CommonModules/            общий модуль
└── Languages/
```

В репозитории только конфигурация: данных (товаров, документов, движений) и готового `.cf` здесь нет.
Служебный `ConfigDumpInfo.xml` тоже не хранится — он меняется при каждой выгрузке.

## Как открыть с нуля

1. Запустите 1С → **Добавить** → **Создание новой информационной базы** →
   «Создание информационной базы без конфигурации для разработки новой конфигурации…».
2. Откройте базу в **Конфигураторе** → **Конфигурация → Открыть конфигурацию**.
3. **Конфигурация → Загрузить конфигурацию из файлов…** → «Загрузить из: **XML-файлы**» → папка `src/cf` из этого репозитория.
4. **Конфигурация → Обновить конфигурацию базы данных** (F7) → «Принять».
5. Запустите режим 1С:Предприятие (F5) и откройте раздел **«Мини-Склад»**. База пустая: заведите пару товаров и контрагентов,
   проведите поступление и реализацию — движения появятся в «Остатки товаров».

То же из командной строки (путь к платформе — ваш):

```bat
"C:\Program Files\1cv8\8.3.27.2342\bin\1cv8.exe" CREATEINFOBASE File="C:\bases\mini-sklad" /AddToList "Мини-Склад"
"C:\Program Files\1cv8\8.3.27.2342\bin\1cv8.exe" DESIGNER /F"C:\bases\mini-sklad" /LoadConfigFromFiles "C:\src\kb99-1c-mini-sklad\src\cf" /UpdateDBCfg
```

## Как проверить контроль остатков

1. Проведите «Поступление товаров»: любой товар — 10 шт.
2. Проведите «Реализацию товаров» на тот же товар — 12 шт. Документ не проведётся, в сообщениях будет
   «Недостаточно товара «…»: нужно 12, на складе 10».
3. Исправьте количество на 10 и проведите: документ проводится. Повторное проведение тоже проходит —
   собственные движения документа в проверке не учитываются.
4. Реализация без строк не проводится: табличная часть «Товары» обязательна.

## Как обновить выгрузку после изменений

Конфигуратор → **Конфигурация → Выгрузить конфигурацию в файлы…** → «Выгрузить в: **XML-файлы**» → папка `src/cf`,
затем коммит. Формат выбирать не нужно: в 8.3.27 диалог сразу выгружает иерархическую структуру, как в репозитории.
Вариант «Архив» складывает выгрузку в один файл — для git он не подходит, изменения не видны построчно.

Из командной строки:

```bat
"C:\Program Files\1cv8\8.3.27.2342\bin\1cv8.exe" DESIGNER /F"C:\bases\mini-sklad" /DumpConfigToFiles "C:\src\kb99-1c-mini-sklad\src\cf" -format Hierarchical
```
